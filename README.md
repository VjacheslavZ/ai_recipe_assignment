# AI Recipe — from an Instagram brand to three finished posts

A reproducible pipeline that takes an Instagram brand (demo: **GymBeam Croatia**,
[@gymbeamhr](https://www.instagram.com/gymbeamhr/), [gymbeam.hr](https://gymbeam.hr))
and produces three ready-to-publish Instagram posts: a carousel, a single image
and a 2–3 frame story. Stages: **brief → brand analysis → content plan → create →
review**. Each stage writes an artifact to `runs/<runId>/` and its status to SQLite,
so a run can be resumed from any stage. Image backgrounds are generated by an
OpenAI image model *without* the product; the real product photo, logo and
headline are composited on top with `sharp`. Every OpenAI call is logged with
model, tokens, cost and duration.

See [docs/PLAN.md](docs/PLAN.md) for the plan and [docs/DECISIONS.md](docs/DECISIONS.md)
for design decisions.

## Requirements

- Node.js 22 (see `.nvmrc`; tested on 22.12)
- pnpm 11 (`corepack enable` or install pnpm globally)
- An OpenAI API key (only for stages that call OpenAI)

## Setup

```bash
pnpm install
cp .env.example .env   # then set OPENAI_API_KEY
```

Native dependencies (`sharp`, `better-sqlite3`, `esbuild`) are allowed to run
their install scripts via `allowBuilds` in `pnpm-workspace.yaml`.

## Commands

| Command | What it does |
| --- | --- |
| `pnpm recipe --help` | CLI help |
| `pnpm recipe run --brief brief.yaml [--from-step 3]` | Run the pipeline (TODO) |
| `pnpm dev:server` | API server (Fastify) on `PORT` (default 3001) with watch |
| `pnpm dev:web` | Web UI (Vite) on http://localhost:5173, proxies `/api` to the server |
| `pnpm typecheck` | Type-check all packages |
| `pnpm test` | Run tests (Vitest) |
| `pnpm build` | Build all packages to `dist/` |

## Repository structure

```
packages/
  core/     pipeline stages, Zod schemas, OpenAI wrapper + cost tracking, sharp compositing
  server/   Fastify REST + SSE, SQLite (Drizzle), in-process job queue
  web/      React + Vite + Tailwind UI
  cli/      `pnpm recipe` command line
brand_kit/
  gymbeamhr/  logo, product photos, Instagram screenshots, fonts (see its README)
runs/       run artifacts, one folder per run (the final demo run is committed)
data/       SQLite database (git-ignored)
docs/       plan and decision log
```
