# AI Recipe — from an Instagram brand to three finished posts

A reproducible pipeline that takes an Instagram brand (demo: **GymBeam Croatia**,
[@gymbeamhr](https://www.instagram.com/gymbeamhr/), [gymbeam.hr](https://gymbeam.hr))
and produces three ready-to-publish Instagram posts in English: a carousel, a
single image and a 2–3 frame story. Stages: **brief → brand analysis → content plan → create →
review**. Each stage writes an artifact to `runs/<runId>/` and its status to SQLite,
so a run can be resumed from any stage. Image backgrounds are generated by an
OpenAI image model *without* the product; the real product photo, logo and
headline are composited on top with `sharp`. Every OpenAI call is logged with
model, tokens, cost and duration.

Runs are started and reviewed in the web UI; the app runs in Docker. See
[docs/PLAN.md](docs/PLAN.md) for the plan and [docs/DECISIONS.md](docs/DECISIONS.md) for design decisions.

## Requirements

- Docker with Compose v2.24+ (Docker Desktop on macOS/Windows)
- An OpenAI API key (without one, `AI_PROVIDER=mock` runs the app on fixtures)

## Start

```bash
cp .env.example .env      # set AI_PROVIDER and, for real runs, OPENAI_API_KEY
docker compose up         # first start builds the image; then open http://localhost:5173
```

Two containers start: `server` (Fastify API, job worker, SQLite) and `web` (Vite). The repository is mounted into both, so editing code reloads live: the server restarts on save (`tsx watch`), the UI hot-reloads (Vite HMR). Database and run folders live in the repo's `data/` and `runs/`, so they survive restarts. Stop with `docker compose down`.

## Commands

| Command | What it does |
| --- | --- |
| `docker compose up` | Start the app on http://localhost:5173 (add `-d` to run in the background) |
| `docker compose logs -f server` | Follow the API and pipeline log |
| `docker compose exec server pnpm test` | Run the tests (Vitest) |
| `docker compose exec server pnpm typecheck` | Type-check all packages |
| `docker compose exec server pnpm add <pkg> --filter @recipe/core` | Add a dependency (updates the lockfile on the host and the container's `node_modules`) |
| `docker compose exec server pnpm install` | Install dependencies after the lockfile changed (e.g. after a pull), then `docker compose restart` |
| `docker compose down` | Stop |

## How to run the recipe

Open http://localhost:5173.

1. **Start a run.** Click "Load the GymBeam example" or paste your own brief (YAML). Optionally upload a logo, product photos and Instagram screenshots for this run only; anything you leave out comes from `brand_kit/<slug>/`. Click **Start run**.
2. **Watch it.** The run page shows the five stages live: brief, brand analysis, content plan, create posts, review. The Log and Costs tabs show every AI call with model, tokens, time and cost.
3. **Answer questions.** When a product price cannot be verified on the brand site, the run stops and asks you in a red block at the top, with a countdown. Enter the price or leave it out; after 10 minutes the price is left out automatically. The runs list and the browser tab show "Answer needed" while a run waits.
4. **Review the posts.** The Posts tab shows the three posts in phone frames: slides in order, QA score per slide, caption with "Copy for Instagram", and the fact-check result. Read "Check before publishing" first. Analysis, Plan and Review tabs show each stage's report.
5. **Redo a part.** "Re-run from here" on any stage runs it and the stages after it again; earlier stages keep their output. Re-running from Create posts reuses the plan and every background whose prompt did not change.
6. **Download.** "Download posts.zip" appears after the review: final slides, captions, `POSTS.md` and `review.md`.

### First run with OpenAI

1. In `.env` set `AI_PROVIDER=openai` and `OPENAI_API_KEY=...`, then `docker compose restart server` (the server reads `.env` at start).
2. On the Start a run page click **Check OpenAI setup**. It checks the key and that the text, vision and image models exist for it, without using tokens.
3. Start the GymBeam example. The default models in `.env.example` are the cheapest ones (`gpt-6-luna`, `gpt-image-1-mini`, low quality, 1024×1024): a test run costs a few cents. The Costs tab shows the spend live.
4. For the final run switch to the models and settings in the comments of `.env.example` (`gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-image-2.5-flare`, `IMAGE_QUALITY=high`, `IMAGE_SIZE=1024x1536`) and restart the server.

Without a key, `AI_PROVIDER=mock` runs every stage on fixtures (placeholder backgrounds, canned analysis and plan) in seconds and at no cost. It checks the app, not the content; mock runs are marked as not publishable in the review.

### What a run produces

```
runs/<brand>_<yyyymmdd-hhmmss>/
  brief.input.yaml, config.json      the brief as given, models and settings (no keys)
  state.json                         stage status, timestamps, errors
  ai_calls.jsonl, cost_report.json   every AI call with tokens, cost and duration
  01_brief/     brief.json, brief.md
  02_analysis/  analysis.json, analysis.md, sources.json
  03_plan/      plan.json, plan.md
  04_create/    post_N/slide_K.png, captions.json, image_prompts.json, compose_specs.json, POSTS.md
  05_review/    posts/ (final slides + caption.txt), review.json, review.md, POSTS.md, posts.zip
```

## Human actions required

| When | Action | Why it cannot be automated |
| --- | --- | --- |
| Setup | Put an OpenAI API key in `.env` (`OPENAI_API_KEY`), set `AI_PROVIDER=openai` | Secret; never committed |
| Before the run | Logo and real product photos in `brand_kit/<slug>/` (or upload them in the UI) | Posts show only real products; the pipeline never generates packaging |
| Before the run | 6–10 screenshots of recent Instagram posts in `brand_kit/<slug>/instagram/` | Instagram blocks automated access; screenshots feed the style analysis |
| Before the run | Check product names and page URLs in the brief (fields marked `VERIFY` / `TODO`) | They are the ground truth for facts and prices |
| During the run | Answer price questions, or skip them | A price is printed only if it is verified on the brand site or confirmed by you |
| After the run | Read the "Check before publishing" list in `review.md` / the Posts tab | Lists slides below the QA threshold, unsupported claims, caption issues |
| After the run | Read the copy; approve or re-run posts | Final responsibility for published copy stays with a person |

## What may vary between runs

Fixed by the inputs: the products and their photos, the logo, which facts and prices may be used (only verified ones, with their URLs), post formats and the slide layouts, canvas sizes, the QA rubric and threshold.

Varies between runs: the wording of headlines and captions, the post concepts, the generated backgrounds (image models are not seeded), the colours and style the analysis reads from the screenshots, which facts the plan picks, and QA scores. Whatever the brand site shows on the day of the run also changes the result, since prices and product facts are researched live; each fact records its URL and date.

To get the same posts again, keep the run folder: re-running from step 4 reuses the plan, and backgrounds are cached by prompt within a run, so only slides whose prompt changed are regenerated.

## Cost & time

Every AI call is logged in `runs/<id>/ai_calls.jsonl` and summed per stage and model in `cost_report.json` (also on the Costs tab). Prices per model are in `packages/core/src/ai/pricing.ts`; calls to a model without a price entry are counted and flagged, so the total is never silently low.

A run makes about 21 AI calls: 2 for the analysis (site research with web search, Instagram screenshots), 1 for the plan, 1 image per slide (8 for three posts), and 1 QA call per slide plus 1 fact check per caption. Each slide below the QA threshold adds one image and one QA call.

- **Development defaults** (`gpt-6-luna`, `gpt-image-1-mini`, low quality, 1024×1024): a few cents per run.
- **Final run** (`gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-image-2.5-flare`, high quality, 1024×1536): measured cost and time of the submitted run are in its `cost_report.json`.

Mock runs finish in seconds. With OpenAI most of the time goes to image generation and web search.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `OPENAI_API_KEY is not set` | Set the key in `.env` and run `docker compose restart server`, or use `AI_PROVIDER=mock` |
| "Check OpenAI setup" shows a model as not found | The model id is wrong or not enabled for the key's project; change it in `.env` and restart the server |
| The UI says "API not reachable" | Check `docker compose logs server`; the server container may have failed to start |
| `sharp` or `better-sqlite3` fails to load, or a package is missing | The container's `node_modules` are stale: `docker compose exec server pnpm install`, then `docker compose restart`. To start clean: `docker compose down -v && docker compose up --build` |
| Code changes do not reload | The server polls for changes (`CHOKIDAR_USEPOLLING` in `compose.yaml`); check `docker compose logs -f server` for "Restarting" |
| The analysis finds no product facts | Check the product URLs in the brief. If the text model rejects the `web_search` tool, set `OPENAI_TEXT_MODEL` to a model that supports it (for example `gpt-5.4-nano`) |
| A stage failed | Fix the cause (brief, brand kit, key), then click **Re-run from here** on that stage |
| Text on slides uses a generic font | Slides use the system sans-serif bold through Pango; brand fonts in `brand_kit/<slug>/fonts/` are not wired in yet |
